## 6. DRIFT

**Code does what the docs forbid / claim done:**
- `budget.py:2` + `README.md:53` claim every paid call is gated; `cheap_llm.py:42-55` and `google_places.py:46-55` spend without `can_spend`.
- OUTREACH_PLAYBOOKS §2 specifies a `touches` table; code folded it into `engagement_events` (`db/007`, documented in decision 003 F2).
- ENRICHMENT_MASTER_PLAN §9 names the queue `jobs`; code ships `job_log` (`db/002:235`).

**Docs assume what the code lacks:**
- `PIVOT_ENGINE.md` (MISSING) assumes a fact graph with `source_fact_id` pivot chains; `enrichment_findings` has no link field (§2a). No graph, no walk.
- `TREASURY.md` (MISSING) assumes an allocator (acquire/settle, grant-gating); `budget.py` has only `can_spend` + `log_cost` + `forecast` — no allocator, no grants.
- `SELF_SERVE_ONBOARDING.md` (MISSING) assumes a self-serve flow; `factory/workers/onboarding.py` `activate_client()` exists but is manual-call only (no UI, no signup path).
- ENRICHMENT_MASTER_PLAN §D3 assumes 80/20 strategy learning/allocation; `strategies`/`strategy_runs` are empty (0 rows) and no code ranks or allocates by score.
- **Biggest:** the master plan describes a factory-fed product on `client_leads`/`companies`/`contacts`; the live client app reads the LEGACY `leads` table (`api/leads.js:24`) and logs sends to `messages_sent` (`api/mark-sent.js`), with the daily cadence hardcoded in `public/app.html` (`cadNext`/`cadOf`, ~line 1077). The playbook engine, planner, ICPs and learning are built and populated but **not consumed by the client-facing surface** (only the admin Reporte view `api/report.js` and Ops view `api/ops.js` read factory tables).

## 7. VERDICT

**What is actually running for the current client today, end to end:** `public/app.html` → `api/leads.js` / `api/mark-sent.js` / `api/me.js` reading and writing the legacy `leads` / `messages_sent` / `actions` tables, with the daily task order computed by the hardcoded `cadNext`/`cadOf` cadence in `app.html`. Separately and invisibly to the client, `factory/service.py` runs `run_nightly` on Railway, enriching `companies`/`contacts`/`client_leads` to `READY` and composing dossiers; email replies are reconciled into `engagement_events`. The Stripe webhook is live but has processed 0 payments.

**The single biggest gap between the docs and reality:** everything the factory builds (playbook engine, structured ICPs, learning, pivot/treasury ambitions) is real in the database but the client-facing app still runs the legacy cockpit on the old `leads` table with a hardcoded cadence. The factory is not wired to the surface the client uses.
